**Document Version:** 1.1.0-LIMITATIONS  
**Date:** November 5, 2026  
**Status:** Canonical Reference Document  
**Applicability:** Aether v1.0.0 (Frozen Release) & Aether v1.1.0 (Planning Baseline)

---

## 1. Purpose & Scope

This document provides a transparent, technically rigorous accounting of all known boundaries, unsupported operations, external dependencies, and hardware constraints in Aether.

Every item is classified under one of five architectural states:
- `[IMPLEMENTED & VERIFIED]`: Feature is complete, verified by tests, and working in v1.0.0.
- `[PLANNED FOR v1.1.0]`: Feature is architecturally designed; implementation scheduled for v1.1.0.
- `[BLOCKED BY EXTERNAL DEPENDENCY]`: Requires upstream framework or library updates.
- `[REQUIRING HARDWARE VALIDATION]`: Requires physical testing on specialized Apple Silicon tiers (64GB–192GB).
- `[REQUIRING CREDENTIALS / ACCOUNTS]`: Requires Apple Developer Program enrollment or notary keys.

## 3. Deep Technical Analysis of Key Limitations

### 3.1 Multimodal Vision Perception
- **Limitation:** In v1.0.0, vision models such as `Qwen 2 VL 7B/2B`, `Pixtral 12B`, and `MiniCPM-V 2.6` function strictly as language models. The UI does not provide an image attachment tray, and `LlamaInferenceWorker` does not invoke `clip_model_load`.
- **Reason:** In llama.cpp architecture, vision-language models require two independent coordinate artifacts: the language GGUF file and an `mmproj-*.gguf` projection matrix. Loading image embeddings into the context window requires the `llava` C-API, which is scheduled for integration in v1.1.0.
- **Roadmap Resolution:** v1.1.0 Priority 1 introduces the `LlamaMultimodalWorker`, dual-file catalog metadata, and SwiftUI image attachment trays.

### 3.2 Specialized Audio and Diffusion Models
- **Limitation:** Models including `Whisper Large v3 Turbo`, `Whisper Base`, `Breeze-TTS 2`, `FLUX.1 Schnell`, and `Stable Diffusion v1.5` cannot be loaded into the text inference engine.
- **Reason:** Audio transcription models and latent diffusion models utilize radically different computational graphs, tokenizers, and sampling algorithms than autoregressive text decoders.
- **Safety Guardrail:** In `ModelHubCardView` and `ModelDetailSheet`, the "Download" button is suppressed and replaced with an informational requirement badge (e.g. `Requires Audio Engine`, `Requires Diffusion Engine`), preventing users from wasting bandwidth on incompatible weights.
- **Roadmap Resolution:** v1.1.0 Priority 2 introduces standalone in-process xcframeworks for Whisper and Stable Diffusion with exclusive Metal arbitration on 8GB/16GB Macs.

### 3.3 DeepSeek V3 671B Hardware Infeasibility
- **Limitation:** The flagship DeepSeek V3 model cannot be downloaded or executed on any consumer or workstation Mac.
- **Reason:**
  1. **Storage Footprint:** The model weights are split into 9 shards totaling **404.43 GB** (`404,430,187,072 bytes`).
  2. **Unified Memory Requirements:** Loading the 671B Mixture-of-Experts weights (even with only 37B active parameters per token) requires mapping the full 404 GB into unified memory. Accounting for KV cache and Metal scratch buffers, the minimum RAM requirement is **420 GB**.
  3. **Apple Silicon Hardware Ceiling:** The highest-end Mac currently manufactured (Mac Studio with M2 Ultra) supports a maximum of **192 GB unified memory**. Running DeepSeek V3 locally is physically impossible on a single Apple Silicon machine.
- **Safety Guardrail:** The catalog entry is explicitly configured as `.incompatible("Requires 404.43GB disk storage & 420GB+ unified memory across 9 shards. Exceeds single Mac hardware limit (192GB max).")`. Ordinary direct download is completely disabled in the UI.

### 3.4 Code Signing & Gatekeeper Distribution
- **Limitation:** The distribution disk image `dist/Aether-v1.0.0-arm64.dmg` is ad-hoc signed (`Signature=adhoc`). macOS Gatekeeper (`spctl`) assesses the binary as `rejected`.
- **User Impact:** When a user downloads `Aether-v1.0.0-arm64.dmg` via Safari or Chrome, macOS assigns the `com.apple.quarantine` extended attribute. On double-clicking `Aether.app`, macOS displays an alert stating the app cannot be opened because Apple cannot check it for malicious software.
- **Workaround:** Users must either:
  1. Open Terminal and execute: `xattr -d com.apple.quarantine /Applications/Aether.app`
  2. Or right-click `Aether.app` in Finder and select **Open**, then click **Open** in the security confirmation dialog.
- **Roadmap Resolution:** v1.1.0 Priority 5 automates Developer ID signing, `xcrun notarytool` submission, and `xcrun stapler staple` once Apple Developer Program credentials are provided to `scripts/package_release.sh`.

### 3.5 Memory Ceilings on Base Apple Silicon (8 GB Macs)
- **Limitation:** On base 8 GB Macs (e.g. M1 MacBook Air), models with $\ge 7\text{B}$ parameters (which require ~4.7 GB for weights + 2 GB for KV cache + 3.5 GB for macOS) cause high memory pressure and paging.
- **Protection:** `DeviceCapabilityEngine.evaluateSuitability()` flags 7B+ models with `High RAM Demand` or `Requires 16GB RAM`, recommending 0.5B–3B parameter models (e.g. `Qwen 2.5 1.5B/3B`, `Llama 3.2 1B/3B`) for optimal, swap-free execution.

### 3.6 Strict App Sandbox & External Tool Daemons
- **Limitation:** Aether intentionally does not launch unconfined child processes or shell interpreters (`/bin/sh`, `/bin/zsh`, `Process()`). External subprocess JSON-RPC MCP daemons are not supported.
- **Security Justification:** Strict adherence to the macOS App Sandbox guarantees that an adversarial model hallucination or prompt injection attack cannot execute arbitrary shell scripts, tamper with user files, or access private system resources. All tools (`safe_calculator`, `system_info`, `sandboxed_file_reader`) execute in-process within explicit sandbox boundaries.
